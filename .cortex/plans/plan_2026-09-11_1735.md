## GitHub Project Catalog

A static Next.js site: searchable thumbnail grid of all 123 `pmjose` repos → click through to a full detail page. Published to GitHub Pages.

**Accepted tradeoff (your call):** private repo names, descriptions, READMEs, and file trees will be publicly visible on Pages, and the committed `repos.json` will contain them. Private-repo OpenGraph thumbnails won't load for anonymous visitors, so I'll add a generated gradient card as the `onError` fallback.

### 1. Data pipeline — `scripts/fetch-repos.mjs`
- One GraphQL call batch for all 123 repos: name, description, visibility, primary language, language breakdown with byte counts, stars, forks, topics, license, created/pushed dates, default branch, homepage, archived flag.
- Per-repo REST/GraphQL fan-out for: README markdown, top-level file tree, last 20 commits, contributors. ~500 requests total, well inside the 5000/hr limit; concurrency capped at 8 with retry.
- Writes `data/repos.json` (index) + `data/repos/<name>.json` (detail). Re-runnable via `npm run refresh`.
- Auth from `gh auth token`, falling back to `GITHUB_TOKEN`.

### 2. Site — Next.js 15 App Router, `output: 'export'`
- `/` — responsive card grid. Thumbnail, name, description, language dot, stars, topic chips.
- Client-side instant search across name + description + topics + language; filter chips for language, visibility, archived; sort by recently-pushed / stars / name.
- `/r/[name]` — statically generated per repo via `generateStaticParams`:
  - Rendered README (markdown-it + sanitize-html, relative image/link paths rewritten to `raw.githubusercontent.com`)
  - Languages breakdown as a stacked percentage bar
  - Top-level file tree
  - Last 20 commits with message, author, date, SHA link
  - Contributors, license, dates, clone URL, "Open on GitHub"
- Visual direction: minimal dark editorial — one accent color, generous spacing, real type scale. No stock-template look.

### 3. Deploy
- `basePath` wired from an env var so Pages subpath routing works.
- `.github/workflows/deploy.yml`: runs the fetch script with a token, builds, uploads the static export, deploys to Pages. Also a scheduled weekly refresh so the catalog stays current.
- Create the repo `pmjose/pj-project-catalog`, push, enable Pages via `gh`.
